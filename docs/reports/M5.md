## What was built

- **core `scoring/`** (plain Java, no Spring): `Scoring.score(ScoreInput)→ScoreResult` — the ONE scoring function both scan-time reconcile and the api re-score call. Base per D-044 (SCA) / D-045 (secret), adjustments on-KEV +5 and repo sensitivity high +5 / low −10, clamp 1–100, SPEC bands; every contribution an itemized `ScoreLine` (deltas sum to the score). `CweDictionary` (resource-backed CWE→phrase, first-id rule, summary fallback). `FixTime` (minor/major semver category + config map).
- **OSV parser enrichment**: per alias group, the chosen CVSS vector (v4>v3), advisory label, CWE ids (array order), CVE aliases and summary, carried `RawFinding → ScanFinding → sub_issue`.
- **`SubIssueScorer`** (both profiles): resolves KEV (any CVE alias) + EPSS (stored only) from the global caches, calls `Scoring`, sets `in_kev/epss/score/score_breakdown`. **`GroupRollupService`** (shared): severity = max open sub score, fix-time = Σ open, subtitle from worst-open CWE phrase (sca/sast/iac only).
- **Intel (api only)**: `IntelFetcher` (KEV JSON + EPSS gz, TLS always on), `KevSyncService` (full refresh), `EpssSyncService` (staged bulk swap — change #3), daily `IntelSyncScheduler` (`ApiSchedulingConfig` enables scheduling in the api profile), `AdminIntelController` manual endpoints, `ReScoreService` (D-049).
- **API**: `SubIssueView` enriched with `score/band/scoreBreakdown/cvss/severityLabel/cwe/cwePhrase/inKev/epss/epssAttribution`.

## OSV field paths persisted & the cvss/severity_label split

- base number: `groups[].max_severity` → `sub_issue.tool_severity` (unchanged from M4); base = `max_severity × 10`, else label fallback.
- `cvss` = `vulnerabilities[].severity[]` vector string, **v4 preferred over v3, null when none** (vector only — change #2).
- `severity_label` = `vulnerabilities[].database_specific.severity` (the no-CVSS base source).
- `cwe` = `vulnerabilities[].database_specific.cwe_ids` (array order kept); `advisory_summary` = `vulnerabilities[].summary`.
- `cve_aliases` = every `CVE-…` in `groups[].ids` + `groups[].aliases`.

The scorer/re-score recompute the base from the persisted inputs (`tool_severity` number, else `severity_label`); nothing scoring-related is read back out of `score_breakdown` jsonb.

## Core scoring signature; one function, two callers

`com.company.secscan.scoring.Scoring.score(ScoreInput) → ScoreResult` (pure). Called by `SubIssueScorer` from **scan-time reconcile** (`ReconcileService`) and from the **re-score job** (`ReScoreService`) — the same function, so a stored score and a recomputed score are identical.

## KEV/EPSS sync trigger & offline-by-default

- Daily `@Scheduled(cron "0 0 4 * * *")` `IntelSyncScheduler.dailySync()` (api profile only) loads KEV + EPSS then calls `ReScoreService.rescoreAll()`. Disable with `secscan.intel.scheduled-sync-enabled=false`.
- Manual re-sync (exact shape): `POST /api/v1/admin/intel/kev/sync`, `POST /api/v1/admin/intel/epss/sync`, `POST /api/v1/admin/intel/rescore` → `{feed, loaded, rescored}`.
- Offline: `IntelSyncIT`/`ReScoreIT` use WireMock + Testcontainers; the real feeds are only in `@Tag("live-intel")` tests, excluded by default (verified in `app/build.gradle.kts`: `if (!project.hasProperty("liveIntel")) excludeTags("live-intel")`). TLS verification is never disabled.

## Fix-time minor/major + no-fixed-version rule

SCA major = installed→fixed **major** version increases → `SCA_MAJOR` (60); else `SCA_PATCH_MINOR` (15). **No `fixed_version` → `SCA_PATCH_MINOR` (15)** (documented default: a null fixed often means no published fix, so remediation estimates are not inflated). Secret → `SECRET_ROTATION` (10). Group `fix_time_minutes` = Σ open sub-issues.

## M5 review fixes (2026-10-19) — addendum

### B1 (blocker) — re-score lost-update fixed
The re-score no longer does a full-entity save. Each open sub-issue's four score columns are written by a **column-scoped, status-guarded UPDATE** (`SubIssueRepository.updateScoreColumnsIfOpen`):

```sql
update sub_issue set score = :score, score_breakdown = cast(:breakdown as jsonb),
       in_kev = :inKev, epss = :epss
 where id = :id and status = 'open'
```

`@Modifying(clearAutomatically = true, flushAutomatically = true)`. `SubIssueScorer.compute()` now returns the outputs **without mutating** the managed entity, so no stray full flush can leak a non-score column. A row reconcile solved in the window is skipped (`WHERE status='open'` → 0 rows), and the group rollup during re-score uses `GroupRollupService.recomputeScoreRollup`, which updates only `severity_score`/`fix_time_minutes`/`subtitle` from a fresh OPEN-rows query and **never writes `issue_group.status`**.
Proof: `ReScoreConcurrencyIT.aSubIssueSolvedInTheWindowIsNotResurrectedByReScore` — solve in the window → UPDATE returns 0, the row stays `solved` with its score 98 (not resurrected to 100), `in_kev` stays false, `solved_at` unchanged, **0 `triage_event`**.

### SF1 / D-052 — SCA group fix-time is one upgrade, not the sum
`GroupRollupService.fixTimeMinutes`: for `type=sca` the group fix-time is the **max** category among open subs (60 if any open sub needs a major bump, else 15); non-sca groups keep the **sum**. Test `ScoringReconcileIT.scaGroupFixTimeIsTheSingleWorstUpgradeNotTheSum` updated from 75 → **60**.

### SF2 — intel empty/short-feed guard
`IntelLoadGuard.shouldReplace` aborts the full-refresh replace (keeps existing rows, logs an error) when the parsed count is 0, below an absolute floor (`min-kev-rows` 100 / `min-epss-rows` 1000), or below `min-retained-fraction` (0.5) of the current table — never delete-then-load-nothing. Malformed EPSS rows are now counted and logged at **warn** (count only, never row content). Tests (`IntelSyncIT`): empty-200 (`{}` / header-only CSV) and HTTP 500 for both feeds each assert the existing rows + the KEV CVE survive.

### SF3 — KEV alias match
