## Warning-code → coverage-banner map (U4, approval item 10)
Source of truth: `ui/src/lib/coverage.ts` (`WARNING_BANNERS` + `coverageBanners`), unit-tested in
`coverage.test.ts`. Built ONLY from stored scan data; never suggests changing the repo (D-030).

Scanner-status lines (from the latest scan's per-scanner task status):
- a task with status `failed`  → "The &lt;noun&gt; scanner failed in the last scan, so its findings were not updated."
- a task with status `timed_out` → "The &lt;noun&gt; scanner timed out in the last scan, so its findings were not updated."
- scanner → noun: `sca`→dependency, `secret`→secret, `sast`→code, `iac`→infrastructure, `eol`→runtime.

Warning-code lines:
| code | banner text |
| --- | --- |
| `UNRESOLVED_PATH` (counted) | "N dependency/dependencies could not be resolved." |
| `MISSING_GRADLE_LOCKFILE` | "Dependencies were resolved without a Gradle lockfile, so results may be less precise." |
| `MISSING_NUGET_LOCKFILE` | "Dependencies were resolved without a NuGet lockfile, so results may be less precise." |
| `GRADLE_BOM_FETCH_FAILED` | "A Gradle BOM could not be fetched, so some dependency versions are unresolved." |
| `GRADLE_UNPARSEABLE_CONSTRUCT` | "Part of a Gradle build file could not be parsed, so some dependencies may be missing." |
| `SCOPE_MANIFEST_UNREADABLE` | "A dependency manifest could not be read, so some dependencies may be missing." |
| `LANGUAGE_DETECT_FAILED` | "Language detection did not complete for the last scan." |
| `EOL_COVERAGE_GAP` | "End-of-life data was incomplete, so some runtimes may not have been checked." |
| `SECSCAN_CONFIG_PARSE_ERROR` | "The repository's .secscan.yml could not be parsed, so its ignore rules were not applied." |
| `SECSCAN_CONFIG_NO_REASON` | "An ignore entry in .secscan.yml was skipped because it had no reason." |
| `SECSCAN_CONFIG_OUTSIDE_CLONE` | "An ignore path in .secscan.yml pointed outside the repository and was skipped." |
| `SCANNER_IMAGE_MISSING` | "A scanner was unavailable for the last scan, so some findings were not updated." |
Order: scanner failures first, then the unresolved-dependency count, then distinct mapped warnings. Unknown
codes are ignored (never surfaced). `SCANNER_TIMEOUT` is intentionally not mapped — the per-scanner task
status already produces the "timed out" line.
