## What was built

Full triage/ignore layer (SPEC "Severity, fix time and triage" + "Manual ignore scopes" + "Triage API (M7)"),
across S1–S6:

- **S1 — `V17__ignore_rule.sql`** — workspace-scoped `ignore_rule` table (five scopes:
  subissue/group/path/cve/rule, global or per-repo) + two nullable `sub_issue` columns (`ignored_by_rule_id`,
  `ignored_at`); FK `ON DELETE SET NULL` so deleting a rule never deletes a finding.
- **S2 — `core/.../triage/`** (plain Java, unit-tested without Spring): `IgnoreMatcher` (D-062 rule+file SAST
  match), `PathExclusion` (default globs + minified + `.secscan.yml` paths), `SecretPlaceholder`, `EpssPolicy`
  (strict bands), `DuplicateRuleMap`, `ReasonCode`, `ReasonAssignment`; plus `core.scoring.Scoring` EPSS tiers.
- **S3 — `.secscan.yml` honored but AUDITED (D-057)** — read **in the scanner container** by
  `scanner-image/secscan_config.py` (`python3 -I`, PyYAML `safe_load` ONLY, symlink-refused + realpath-confined,
  whitelist + caps, raw bytes never leave the container), emitted in the manifest, applied by the worker at
  reconcile triage step 9: `exclude.paths`→`EXCLUDED_PATH`; `ignore.cves{reason}`→`IGNORE_RULE` (materialized as
  idempotent system rules, `created_by='secscan.yml'`, with a revoke lifecycle); `include_dev_dependencies`→
  dev-deps precedence.
- **S4 — declared dev/test scope (D-059)** — `scope_inventory.py` reads DECLARED scope in-container (Maven test
  scope / npm devDependencies / Gradle test configs). `DEV_DEPENDENCY`/`TEST_SCOPE` auto-ignore only when
  `effective_include_dev = repository.include_dev_deps OR .secscan.yml include_dev_dependencies` is false;
  unclassifiable deps stay visible. Finally wires `repository.include_dev_deps` (a no-op until now).
- **S5 — manual ignore/unignore (D-058)** — `TriageService` + `TriageController` create/remove rules and list the
  Ignored view across all five scopes; `TriageStatusResolver` computes the unignore status (keyed on the latest
  scan where the finding's scanner succeeded).
- **S6 — EPSS toggle (D-060) + duplicate-rule (D-061) + `SECRET_PLACEHOLDER`** — `workspace.settings` (jsonb)
  mapped; `WorkspaceSettingsService` + `GET/PUT /workspace/settings`. On = EPSS<1% & not-KEV auto-ignore
  `LOW_EPSS` (status + `triage_event`, at reconcile AND as an immediate on-toggle sweep); the <5% −10 / 5–10% −5
  tiers are scoring-only (no `triage_event`, strict bands → no double-apply). Duplicate SAST rule: curated
  `{stock → winning custom}` map (seeded with the REAL CSRF pair from Opengrep output) auto-ignores the stock
  LOSER `DUPLICATE_RULE` when the winner fired for the same file in the same scan — both keep firing, no
  fingerprint change.

## Migrations

`V17` is additive and applies on top of `V16`; V1–V16 are untouched (no edits, no checksum change). Two nullable
`sub_issue` columns, no backfill. Proven by `V17MigrationIT`.

```sql
-- M7: the manual-ignore model (D-058). Users triage findings by creating ignore_rule rows (SPEC "Manual ignore
-- scopes"): this sub-issue, this group, a path prefix (per repo), a CVE (global or per repo), or a rule id
-- (global or per repo). .secscan.yml CVE ignores are materialized as idempotent SYSTEM rules (created_by =
-- 'secscan.yml', D-057). Apply/remove runs through reconcile and writes a triage_event for every status change
-- (domain rules 2-4).
--
-- Additive only; V1-V16 untouched. Every business table carries workspace_id and every query filters by it
-- (domain rule 1). ignore_rule is per-tenant business data, so it carries workspace_id (unlike the D-050 global
-- intel caches).
create table ignore_rule (
    id            uuid        primary key,
    workspace_id  uuid        not null references workspace (id),
    scope         text        not null check (scope in ('subissue', 'group', 'path', 'cve', 'rule')),
    -- NULL = a global rule (applies across every repository in the workspace); otherwise scoped to one repo.
    repository_id uuid        references repository (id),
    -- The value matched per scope: subissue = fingerprint (SAST matches on rule_id|file_path, D-062);
    -- group = group_key; path = a repo-relative path prefix; cve = a CVE id; rule = a rule id.
    match_value   text        not null,
    -- Human reason (SPEC: every ignore requires one). For a .secscan.yml CVE rule this is the repo-authored
    -- reason; for a manual rule the user's reason. NOT NULL.
    reason        text        not null,
    -- 'secscan.yml' for the materialized in-repo-config rules (D-057), else the acting user (an id/email; a
    -- literal 'system' is used until M10 roles). Never a secret.
    created_by    text        not null,
    created_at    timestamptz not null default now()
);

create index idx_ignore_rule_workspace on ignore_rule (workspace_id);
create index idx_ignore_rule_lookup on ignore_rule (workspace_id, scope, match_value);
create index idx_ignore_rule_repository on ignore_rule (repository_id);
-- Idempotent re-materialization of .secscan.yml rules each scan (D-057 revoke lifecycle): a repo-scoped system
-- rule is unique per (workspace, repository, scope, match_value) so the worker can upsert without duplicating.
create unique index uq_ignore_rule_repo_scoped
    on ignore_rule (workspace_id, repository_id, scope, match_value)
    where repository_id is not null;
create unique index uq_ignore_rule_global
    on ignore_rule (workspace_id, scope, match_value)
    where repository_id is null;

-- Which rule (if any) currently holds a sub_issue ignored, and when it was ignored. ON DELETE SET NULL (D-058,
-- review change #2): deleting a rule must never delete the finding — the unignore path clears the status and
-- writes a triage_event. ignore_reason (V8) now carries the reason CODE (EXCLUDED_PATH / IGNORE_RULE / ...);
-- the human reason comes from ignore_rule.reason via ignored_by_rule_id. Both columns nullable, no backfill.
alter table sub_issue add column ignored_by_rule_id uuid references ignore_rule (id) on delete set null;
alter table sub_issue add column ignored_at timestamptz;
```

## API changes

All under `/api/v1`, record DTOs, server-side pagination (`PagedResponse`), workspace-scoped. Documented in
`docs/SPEC.md` ("Triage API (M7)"). Until M10 wires an authenticated principal (OD-9), a manual rule's
`created_by` is `"user"`.

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/ignore-rules` `{scope, repositoryId?, matchValue, reason}` | Create a generic rule (path/cve/rule; global when `repositoryId` null) and apply it |
| POST | `/sub-issues/{id}/ignore` `{reason}` | Ignore one sub-issue (subissue scope; SAST matches rule+file, D-062) |
| POST | `/issue-groups/{id}/ignore` `{reason}` | Ignore a whole group |
| DELETE | `/ignore-rules/{id}` | Remove a rule; held findings return to the reconcile-computed status |
| GET | `/ignore-rules` | List active rules (paged) |
| GET | `/ignored` | The Ignored view: each ignored finding with reason code, rule and creator (paged) |
| GET / PUT | `/workspace/settings` | Read/update the EPSS auto-ignore toggle |
