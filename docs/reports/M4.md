# Milestone report: M4 Dependencies (SCA)

Branch: `feature/m4-sca` · Commit: `5139a20` · Date: 2026-10-16 · Model(s) used: Claude Opus 4.8

M4 adds dependency scanning (SCA) with **OSV-Scanner v2.7.0** in the scanner image. The worker now runs two
scanners per scan (secrets + SCA) in the one disposable container; OSV output is parsed into one SCA finding per
alias group, enriched (ecosystem, installed/fixed version, repo-relative manifest path) and reconciled into the
M3 issue model keyed by repository + ecosystem + package + vuln id. Coverage gaps (missing lockfiles, unresolved
versions, no manifests) are surfaced as `scan_warning` rows, never hidden (D-030). Scope is held to the SPEC M4
row; the static Gradle resolver, NuGet transitive-without-lockfile and private-registry detection are M4b.

## Migrations

Two new, additive migrations (V1–V9 untouched). **V10 and V11 are frozen** — both have been applied to the dev DB
and must never be edited; any further change is a new migration.

### `V10__scan_fail_reason.sql`
```sql
-- Slice-0 hardening: a short machine code explaining why a scan is in status 'failed' (e.g. HOST_NOT_ALLOWED,
-- SCANNER_IMAGE_MISSING, DOCKER_ERROR, WORK_ROOT_NOT_WRITABLE, SCANNER_TIMEOUT, NO_ACCESSIBLE_CONNECTION), so a
-- permanent failure is auditable and the M8 UI can explain it. Null for non-failed scans. Additive, nullable
-- (V1-V9 are immutable once applied; new behaviour is always a new migration).
alter table scan add column fail_reason text;
```

### `V11__sca_support.sql`
```sql
-- M4 SCA support. Three additive changes (V1-V10 are immutable once applied):
--
-- 1. scan_warning: scan-health warnings surfaced per scan (SPEC data model; D-030/D-031) — a coverage gap we
--    show, never hide. code is a machine code (MISSING_GRADLE_LOCKFILE, MISSING_NUGET_LOCKFILE,
--    UNRESOLVED_VERSION, NO_MANIFESTS); file_path is the repo-relative build file, or null when repo-wide.
-- 2. scan_finding.ecosystem: the SCA ecosystem (Maven/npm/NuGet/…) so the issue group key is
--    repo + ecosystem + package (SPEC "Grouping", plan change #7) and the same package name in two ecosystems
--    forms two groups.
-- 3. scan_task.closes_findings: whether a SUCCESSFUL scanner is authoritative to close its missing findings
--    this scan. False for an SCA task that found no packages (OSV exit 128): the scan is ok but must not
--    mass-solve existing SCA issues (D-034, plan change #1). A failed/timed-out task closes nothing regardless.

create table scan_warning (
    id            uuid        primary key default gen_random_uuid(),
    workspace_id  uuid        not null references workspace (id),
    repository_id uuid        not null references repository (id),
    scan_id       uuid        not null references scan (id) on delete cascade,
    code          text        not null,
    message       text        not null,
    file_path     text,
    created_at    timestamptz not null default now()
);

create index idx_scan_warning_workspace on scan_warning (workspace_id);
create index idx_scan_warning_scan on scan_warning (scan_id);
create index idx_scan_warning_repository on scan_warning (repository_id);

alter table scan_finding add column ecosystem text;

alter table scan_task add column closes_findings boolean not null default true;
```

## Decisions added (one line each)

- **D-030** — Scanned repositories are never modified; coverage gaps are shown (as `scan_warning`), not hidden.
- **D-031** — Gradle/.NET without lockfiles in M4: warn + partial results; the static Gradle resolver is M4b.
- **D-032** — Public package registries assumed; private-registry detection is M4b (resolves OD-3).
- **D-033** — Scanner egress stays on the default bridge network for M4 (revisit before any deployment or M10,
  whichever comes first); the future allowlist names GitLab, `api.osv.dev`, `api.deps.dev`, `repo.maven.apache.org`.
- **D-034** — OSV-Scanner pinned to **v2.7.0** by checksum; `scan source -r --format json`, default deps.dev data
  source; exit 128 = no packages (ok, not authoritative to close).
- **D-035** — .NET SCA uses OSV's native `.csproj`/CPM extraction (plan change #4 dropped); the parser drops a
  `.csproj`-sourced NuGet finding unless that `.csproj` raised `MISSING_NUGET_LOCKFILE` (lockfile authoritative).

## Known gaps (shown, not hidden)

- **Gradle without a lockfile:** warning only (`MISSING_GRADLE_LOCKFILE`); OSV resolves nothing without a
  lockfile. Static resolution is M4b (D-031).
- **NuGet without a lockfile:** direct `<PackageReference>` versions only; transitive deps not seen
  (`MISSING_NUGET_LOCKFILE`). M4b (D-031).
- **npm `devDependencies` and Gradle test configurations are NOT excluded** from SCA — OSV-Scanner v2.7.0's JSON
  exposes no dependency-group ("dev") marker to filter on. `repository.include_dev_deps` exists (since M1/V4) but
  **has no effect yet**. Deferred to M7's `DEV_DEPENDENCY` auto-triage.
- **Private registries:** packages that resolve only against a private registry show no advisories (public data
  only). Detection is M4b (D-032).
- **Scanner egress** is still the open default bridge network (D-033); the lockdown to an allowlist is deferred,
  to be revisited before any deployment or at M10, whichever comes first.

## Known nits (not fixed in M4)

- `scan_task.duration_ms` has whole-second granularity (the scanner times in seconds, ×1000).
- `POST /repositories/{id}/scans` returns `createdAt` = null in the response body.
- The worker also runs Flyway migrations on startup. Candidate decision for a later milestone: only the `api`
  profile migrates, and the `worker` validates.
