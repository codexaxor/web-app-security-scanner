## What was built

- `core/.../crypto/TokenCipher.java` — AES-256-GCM (random 12-byte IV per encrypt, 128-bit tag, output
  `base64(IV||ct+tag)`); `fromBase64Key` requires a key decoding to exactly 32 bytes; decrypt verifies the tag
  (wrong key / tamper fails loudly, never echoes ciphertext or key).
- `app/.../config/EncryptionConfig.java`, `TokenCipherHolder.java`, `EncryptionNotConfiguredException.java` —
  wire the cipher from `SECSCAN_ENCRYPTION_KEY`: valid key → available; invalid key → **startup fails**; absent →
  app starts, save/use throws a clear "encryption not configured" error (never a plaintext fallback).
- `app/.../gitlab/GitLabClient.java` — read-only GitLab REST v4 client (Spring `RestClient`, explicit 10s/15s
  timeouts). Token only in the `PRIVATE-TOKEN` header, never in a URL; TLS verification never disabled. Methods:
  `version`, `tokenInfo`, `resolveGroup` (url-encoded path), `listGroupProjects` (follows `x-next-page`),
  `projectLanguages`. Maps 401→INVALID_TOKEN, 403→MISSING_SCOPES, 404→GROUP_NOT_FOUND, 429→RATE_LIMITED,
  timeout/connect-refused→UNREACHABLE, else UNEXPECTED.
- `app/.../gitlab/GitLabError.java`, `GitLabException.java`, `dto/{GitLabVersion,GitLabTokenInfo,GitLabGroup,GitLabProject}.java`
  — error categories and response records; `GitLabProject.isEmpty()` (no default branch) and `markedForDeletion()`.
- `app/.../gitlab/GitLabConnectionService.java` — `test` (no persistence) and `save` (persist, token encrypted
  only after a successful test). Checks required scopes `[read_api, read_repository]`, rejects inactive/revoked
  and past-expiry tokens, warns when expiring within `EXPIRY_WARN_DAYS` (14). One connection per workspace
  (default workspace in M1).
- `app/.../gitlab/GitlabConnection.java` + `GitlabConnectionRepository.java` — entity (ciphertext, group full
  path + numeric id, scopes, expiry) and Spring Data repo (`findByWorkspaceId`).
- `app/.../repository/{Repository,RepositoryRepository,RepositoryService}.java` — `listProjects`
  (server-side pagination; excludes archived + marked-for-deletion; flags empty repos as not-selectable;
  per-page language fetch via `safeLanguages`, which swallows per-project GitLab errors), `select` (persists /
  reactivates, dedup via unique `(workspace_id, gitlab_project_id)`), `listSelected`.
- `app/.../gitlab/api/*` + `repository/api/*` + `api/{PagedResponse,ApiExceptionHandler}.java` — request/view
  records, paginated response wrapper, `@RestControllerAdvice` mapping our exceptions to JSON error bodies
  (never includes the token).
- `app/.../gitlab/GitLabController.java`, `repository/RepositoryController.java` — REST under `/api/v1`.
- `ui/src/{api.ts,App.tsx}`, `ui/src/components/{SignInGate,ConnectGitLab,SelectRepositories}.tsx` — Connect
  and Repositories screens; an in-memory Basic-auth gate (no login screen yet; credentials never persisted).

## Migrations

`app/src/main/resources/db/migration/V4__gitlab_connection_and_repository.sql`:

```sql
-- M1: one GitLab connection per workspace, and the repositories selected from its group.
-- Tokens are stored only as AES-256-GCM ciphertext (never plaintext).

create table gitlab_connection (
    id                        uuid        primary key,
    workspace_id              uuid        not null references workspace (id),
    base_url                  text        not null,
    group_full_path           text        not null,
    gitlab_group_id           bigint      not null,
    token_ciphertext          text        not null,
    token_scopes              text,
    token_expires_at          date,
    webhook_secret_ciphertext text,
    created_at                timestamptz not null default now(),
    -- Single active connection per workspace in M1 (model stays open to more later).
    constraint uq_gitlab_connection_workspace unique (workspace_id)
);

create table repository (
    id                  uuid        primary key,
    workspace_id        uuid        not null references workspace (id),
    connection_id       uuid        not null references gitlab_connection (id),
    gitlab_project_id   bigint      not null,
    path_with_namespace text        not null,
    default_branch      text,
    active              boolean     not null default true,
    sensitivity         text        not null default 'normal'
                          check (sensitivity in ('low', 'normal', 'high')),
    include_dev_deps    boolean     not null default false,
    languages           jsonb       not null default '[]'::jsonb,
    last_scanned_sha    text,
    created_at          timestamptz not null default now(),
    constraint uq_repository_workspace_project unique (workspace_id, gitlab_project_id)
);

create index idx_gitlab_connection_workspace on gitlab_connection (workspace_id);
create index idx_repository_workspace on repository (workspace_id);
create index idx_repository_connection on repository (connection_id);
```

Applies on an empty DB (proven by `BaselineMigrationIT` and the connection/selection ITs, which run Flyway from
scratch on a fresh Testcontainers Postgres). V1–V3 untouched.

## Review fixes (applied after the first report)

Driven by the review brief; all covered by tests unless noted.

1. **Manual Done-when done** — recorded above (PASS).
2. **JSON 401 without `WWW-Authenticate`** — `SecurityConfig` now uses a custom `AuthenticationEntryPoint` that
   returns `{"error":"UNAUTHORIZED",...}` and omits the header, so the browser's native Basic popup never
   appears. Proven by `ApiSecurityIT`. The UI sign-in gate now verifies credentials against a protected endpoint
   and shows **"Wrong email or password."** on 401 (`SignInGate.tsx`).
3. **Group path accepts a pasted URL** — `GitLabGroupPath.normalize` strips host, the `groups/` prefix and any
   `/-/…` suffix, and **rejects a URL for a non-allowlisted host**. Unit tests in `GitLabGroupPathTest`. The
   Connect field label/placeholder now says "path or URL".
4. **Re-save / group change** — re-saving the same group (e.g. token rotation) updates the existing row (new
   ciphertext, scopes, expiry) and **keeps selected repositories**; pointing an existing connection at a
   different group is rejected with a clear `CONNECTION_GROUP_MISMATCH` message. `GitLabConnectionIT`
   (`resavingSameGroupRotatesTokenAndKeepsSelectedRepositories`, `savingADifferentGroupIsRejected`).
5. **Outbound host allowlist** — `SECSCAN_GITLAB_ALLOWED_HOSTS` (comma list, empty = deny all); every outbound
   call requires `https` + an allowlisted host (loopback may use `http`), else `HOST_NOT_ALLOWED`. `GitLabClient`
   enforces it before any request. `GitLabHostPolicyTest` + `GitLabClientTest` (disallowed host / non-https).
   Added to `.env.example` and README (D-018).
6. **Error mapping** — a 404 on a non-group call now maps to `NOT_FOUND`; `GROUP_NOT_FOUND` is used only for
   group resolve. `GitLabClientTest.notFoundOnNonGroupCallMapsToNotFound`.
7. **Decisions** — D-018 (allowed hosts) and D-019 (repo dedup / connection ownership; reassign-or-deactivate
   implemented in M1b) recorded in `docs/DECISIONS.md`.

**Second review round (`/review-pr`):**

8. **Redirects are never followed** (should-fix) — `GitLabClient` uses `JdkClientHttpRequestFactory` over
   `HttpClient.newBuilder().followRedirects(NEVER)` (10s connect / 15s read kept). A 3xx is surfaced as
   `UNEXPECTED_REDIRECT` and never followed, so the `PRIVATE-TOKEN` header cannot be replayed to another host.
   `GitLabClientTest.redirectIsNotFollowedToAnotherHostAndTokenNeverLeaks` (302 → another host; the target
   receives zero requests).
9. **Blank group path → 400** (nit) — normalization now throws `INVALID_GROUP_PATH` (mapped to 400), not
   `GROUP_NOT_FOUND`. `GitLabGroupPathTest.rejectsBlankInputAsInvalidGroupPath`.
10. **`save()` looks up the connection once** (nit) — a single `findByWorkspaceId` is reused for the
    group-change check and the upsert.

## Known gaps / TODOs

- **Real-GitLab Done-when is unverified** — needs the token + VPN; manual step above, to be run before merge.
- Key rotation is not implemented; changing `SECSCAN_ENCRYPTION_KEY` makes stored tokens unreadable (documented
  in README; reconnect required).
- Single connection / single group per workspace in M1; changing an existing connection to a different group is
  rejected for now. Multiple connections and project-mode targets are the next milestone (M1b), already scoped.
- The UI sign-in gate holds Basic credentials in memory only; the real auth UI and roles come in M10.
- `webhook_secret_ciphertext` column is present but unused until change-detection work.
- **GitLab I/O happens inside `@Transactional`** in `GitLabConnectionService.save` and `RepositoryService`
  (the test/listing calls run while a DB transaction is open, holding a connection during network I/O). Harmless
  at M1's single-connection scale; to be fixed in M2 by doing the GitLab calls outside the transaction and only
  opening a short transaction for the persist.
