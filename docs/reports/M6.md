## Migrations (in full)

**V16__eol_cycle.sql** — the one new migration; a GLOBAL reference cache with **no `workspace_id`** (D-050),
column types mirror the endoflife.date v1 release object:

```sql
create table eol_cycle (
    product       text    not null,
    cycle         text    not null,
    is_eol        boolean not null,
    eol_from      date,
    latest        text,
    latest_date   date,
    release_date  date,
    is_lts        boolean not null default false,
    is_maintained boolean not null default false,
    synced_at     timestamptz not null default now(),
    primary key (product, cycle)
);
```

**Migration safety:** additive only (`create table`); V1–V15 untouched; proven on an empty DB by
`EolMigrationIT`. No new business column was added — the `sub_issue`/`issue_group`/`scan_finding` `type` CHECK
already allows `sast`/`iac`/`eol` (V6/V8), SAST reuses `rule_id`/`file_path`/`snippet_hash`, IaC reuses `package`
for the resource, and EOL reuses `package`/`installed_version` for product/cycle (`ReconcileService.fingerprintOf`).
Fix-time categories (`SAST_INJECTION 30`, `IAC_MISCONFIG 15`, `EOL_UPGRADE 300`, `DEFAULT 20`) were already
seeded in V13.
