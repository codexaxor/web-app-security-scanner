## 3. V23 SQL (`V23__multi_tenant_signup.sql`, the only migration)

```sql
-- M8.10 (D-093, D-094, D-097, D-098): self sign-up with operator approval.
-- Pending sign-ups are NOT app_user rows: they live in signup_request (pre-tenant, D-098). app_user keeps
-- workspace_id NOT NULL. The workspace + app_user are created at APPROVAL, in one transaction.

-- ---------------------------------------------------------------- app_user: status + operator
alter table app_user
    add column status            text        not null default 'active',
    add column is_operator       boolean     not null default false,
    add column status_changed_at timestamptz,
    add column status_changed_by uuid        references app_user (id);

alter table app_user add constraint ck_app_user_status
    check (status in ('active', 'disabled'));
-- The operator can never be disabled (it would lock the platform out).
alter table app_user add constraint ck_app_user_operator_active
    check (not is_operator or status = 'active');
-- At most one operator (D-094: the platform operator). Never a second one silently.
create unique index uq_app_user_single_operator on app_user ((true)) where is_operator;

-- Backfill: existing users are active (column default). Promote the bootstrap admin = earliest real (email)
-- admin in Default — ONLY if no operator exists (approval item 4). Demo users (no '@') never qualify.
update app_user set is_operator = true
 where not exists (select 1 from app_user o where o.is_operator)
   and id = (select u.id from app_user u
              where u.workspace_id = '00000000-0000-0000-0000-000000000001'
                and u.role = 'admin' and u.email like '%@%' and u.status = 'active'
              order by u.created_at, u.id
              limit 1);

-- ---------------------------------------------------------------- signup_request (pre-tenant, D-098)
create table signup_request (
    id                       uuid        primary key,
    email                    text        not null,
    password_hash            text,                       -- bcrypt; cleared once decided
    requested_workspace_name text        not null,
    status                   text        not null default 'pending',
    created_at               timestamptz not null default now(),
    decided_at               timestamptz,
    decided_by               uuid        references app_user (id),
    workspace_id             uuid        references workspace (id),   -- the workspace created on approval
    constraint ck_signup_request_status   check (status in ('pending', 'approved', 'rejected')),
    constraint ck_signup_request_email    check (email = lower(email) and position('@' in email) > 1),
    constraint ck_signup_request_ws_name  check (length(btrim(requested_workspace_name)) between 1 and 80),
    constraint ck_signup_request_decision check (
           (status = 'pending'  and password_hash is not null and decided_at is null
                                and decided_by is null and workspace_id is null)
        or (status = 'rejected' and password_hash is null and decided_at is not null
                                and decided_by is not null and workspace_id is null)
        or (status = 'approved' and password_hash is null and decided_at is not null
                                and decided_by is not null and workspace_id is not null))
);
-- One PENDING request per email; a rejected email may sign up again (approval item 1).
create unique index uq_signup_request_pending_email on signup_request (lower(email)) where status = 'pending';
create index idx_signup_request_status_created on signup_request (status, created_at);

-- ---------------------------------------------------------------- fair use (D-097)
-- Fast "does this workspace already have a running job?" for the claimer (see §2 for the state constraint).
create index idx_scan_job_workspace_running on scan_job (workspace_id) where state = 'running';
```

Notes beyond the approval text (flagged for review):
- `signup_request.workspace_id` (nullable, set only on approval) gives traceability from a request to the
  workspace it created; it is not a scoping column.
- `password_hash` is cleared on approve (copied to the new `app_user`) and on reject, so no credential hash
  lingers on decided rows.
- `uq_app_user_single_operator` makes "at most one operator" a DB invariant (a second operator needs a new
  decision + migration).

Cross-table email uniqueness (app_user ∪ pending signup_request): the sign-up and approve transactions take
`pg_advisory_xact_lock(hashtext('signup:' || lower(email)))`, then check `app_user.lower(email)` (existing unique
index `uq_app_user_email_lower`, V3) and pending `signup_request` (`uq_signup_request_pending_email`). Approve
re-checks `app_user` (a bootstrap/demo row could have appeared) → 409 `EMAIL_TAKEN`.

## 4. Behaviour summary

- **Sign-up** `POST /api/v1/auth/signup` (public, JSON-only, CSRF-exempt like login): email, password (≥ 12 chars,
  ≤ 72 bytes), workspace name (1–80). Always **202 + identical body** whether new, already an `app_user`, or
  already pending; bcrypt runs in every branch (timing). Validation errors → 400 (shape only, no existence info).
  Per IP 5 / 15 min → 429 + `Retry-After`.
- **Login** (JSON + Basic share one `AuthenticationManager`): wrong password → 401 as today. Correct password:
  pending `signup_request` → **403 `ACCOUNT_PENDING`**; disabled `app_user` → **403 `ACCOUNT_INACTIVE`** (JSON
  login; Basic → generic 401). Status is checked *after* the password (Spring's pre-auth check would leak it).
  A per-request filter reloads the principal's `app_user.status` by id → a disabled user's live session ends on
  the next request (invalidate + 401).
- **Login rate limits** (failures, sliding 15 min): per (account, IP) 5, per IP 20, per account 50 → 429. A
  success clears that (account, IP) counter only.
- **Client IP**: `SECSCAN_TRUSTED_PROXIES` (CIDR list, default loopback only). `X-Forwarded-For` is honoured only
  when the direct peer is trusted; nginx (`ui/nginx.conf`) overwrites it with `$remote_addr`.
- **Operator API** (all `/api/v1/admin/**` → `ROLE_OPERATOR`, both chains; non-operator → 403):
  `GET /admin/sign-ups?status=pending` (paged), `POST /admin/sign-ups/{id}/approve` (one tx: workspace + active
  app_user + request approved), `POST /admin/sign-ups/{id}/reject`, `GET /admin/users` (paged: email, status,
  workspace name, created), `POST /admin/users/{id}/disable` (409 for the operator/self), `POST
  /admin/users/{id}/enable`. Operator has **no** read access to other tenants' data (D-094).
- **`GET /auth/session`** adds `workspaceName` and `operator`.
- **Fair use**: claimer takes `pg_advisory_xact_lock(<const>)` then claims at most the oldest queued job per
  workspace that has no running job (others wait). Repository limit: active repos per workspace ≤ 25 (all
  workspaces incl. Default, configurable `secscan.fair-use.max-repositories`), enforced in the DB-only tx after
  any provider fetch with `SELECT … FOR UPDATE` on the workspace row; covers select, public add, reattach,
  `PATCH active=true`; a batch that would exceed it is refused whole → 409 `REPOSITORY_LIMIT_REACHED`.
  Existing repos above the limit are kept.
- **Demo mode** unchanged, Default workspace, never operator (so no `/admin/**`).

### S7 repair (2026-11-05)

The original `7a3a615` was committed although its gate was **BUILD FAILED** (the commit command did not check
the gate's exit code). Approved fix, amended into that unpushed commit so every commit on the branch is green:

- `ScanMigrationIT.claimReturnsRunnableJobsOldestFirstAndSkipsFutureOnes` is an **intended D-097 behaviour
  change, not a weakening**: it expected two runnable jobs of the SAME workspace to be claimed together, which
  D-097 forbids. It now uses two workspaces (still proves oldest-first and future `run_after` skipped) and adds
  the D-097 assertion that a second runnable job of the same workspace is not returned.
- D-097 now documents that a concurrent-request race can leave a batch partly applied, never above 25 active.
- From here on every commit runs as one command: `./gradlew build && git commit …`.
