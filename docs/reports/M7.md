## 1. Scope delivered

The full triage/ignore layer (SPEC "Severity, fix time and triage"):

- **Manual ignore model (D-058)** — `V17` adds the workspace-scoped `ignore_rule` table (five scopes:
  subissue/group/path/cve/rule, global or per-repo) and two nullable `sub_issue` columns (`ignored_by_rule_id`,
  `ignored_at`); the FK is **`ON DELETE SET NULL`** so deleting a rule never deletes a finding. `TriageService`
  + `TriageController` create/remove rules and list the Ignored view; `TriageStatusResolver` computes the
  unignore status.
- **`.secscan.yml` honored but AUDITED (D-057)** — read **in the scanner container** by
  `scanner-image/secscan_config.py` (`python3 -I`, PyYAML `safe_load` ONLY, symlink-refused + realpath-confined,
  whitelist + caps, raw bytes never leave), emitted in the manifest, applied by the worker at reconcile triage
  step 9: `exclude.paths`→EXCLUDED_PATH, `ignore.cves{reason}`→IGNORE_RULE (materialized as idempotent system
  rules with a **revoke lifecycle**), `include_dev_dependencies`→dev-deps precedence.
- **Auto-triage reason codes (D-059)** — `EXCLUDED_PATH` (SPEC default globs + minified + `.secscan.yml` paths),
  `SECRET_PLACEHOLDER`, `DEV_DEPENDENCY`/`TEST_SCOPE` (from DECLARED scope read by our own in-container inventory
  `scope_inventory.py` — Maven test scope / npm devDependencies / Gradle test configs; unclassifiable deps stay
  visible), `LOW_EPSS` (D-060), `DUPLICATE_RULE` (D-061), `IGNORE_RULE` (manual + `.secscan.yml`). Finally wires
  `repository.include_dev_deps` (a no-op until now); `effective_include_dev = repo OR .secscan.yml` (the file may
  only INCREASE visibility).
- **EPSS toggle (D-060)** — `workspace.settings` (jsonb) now mapped; `WorkspaceSettingsService` +
  `GET/PUT /api/v1/workspace/settings`. On = EPSS<1% & not-KEV auto-ignore `LOW_EPSS` (status + `triage_event`,
  at reconcile AND as an immediate on-toggle sweep); the <5% −10 / 5–10% −5 tiers are scoring-only (scorer +
  re-score, no `triage_event`, strict bands → no double-apply).
- **Duplicate SAST rule (D-061)** — a curated `{stock → winning custom}` map (seeded with the REAL CSRF pair
  captured from Opengrep output) auto-ignores the stock LOSER `DUPLICATE_RULE` when the winner fired for the same
  file in the same scan; both keep firing, no fingerprint change.

All status changes flow through reconcile / the triage services and write a `triage_event`; a failed/absent
scanner still closes nothing; an active rule keeps a finding ignored (hard rule 6). Auto-ignores clear via their
cause at reconcile/on-toggle (a `triage_event`); manual unignore (the `DELETE`) applies to manual ignores.

## 5. Bug found & fixed in-slice

- **SECRET_PLACEHOLDER false-ignore of a real secret** — the placeholder matcher first treated the masked
  preview `****` as a placeholder, but `****` is the D-027 mask for ANY short/real secret, so a real short secret
  (e.g. the private-key fixture) was wrongly auto-ignored. Caught by the secret reconcile ITs
  (`SecretEngineSwapReconcileIT`, `ReconcileServiceIT`) in the S6 full build; fixed by removing `****` from the
  placeholder prefixes (`core.triage.SecretPlaceholder`) with a regression test.
- **`workspace.settings` NOT NULL on entity insert** — mapping the jsonb column made entity inserts send `null`
  (violating the NOT NULL default-`'{}'` column); fixed by initializing the field so inserts send non-null JSON.
