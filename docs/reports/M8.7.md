## Migrations
**V22** `V22__provider_neutral_sources.sql` — the only migration (V1–V21 frozen). Additive, no table/column
rename. `gitlab_connection` gains `provider`, `credential_kind`, `owner_login`, `repo_full_name`,
`provider_repo_id`, and a generated `host` (authority of `base_url`); the V5 target-type enum is widened to
group/project/owner/repo; `token_ciphertext` becomes nullable with a credential-kind check; the uniqueness
indexes now include provider + host. `repository` gains `provider`, `host`, `provider_repo_id`;
`gitlab_project_id` becomes nullable (null for GitHub); identity index is
`(workspace_id, provider, host, provider_repo_id)`. Existing rows backfill as GitLab on their current host
(a BEFORE INSERT trigger fills repository identity on legacy inserts; a host RAISE guards the unresolvable case).
**Proof:** `MigrationV22IT` on an empty DB and on a seeded pre-V22 DB (ids + findings identical before/after).
The full SQL is in `docs/reports/M8.7-worklog.md`.

## API changes (additive, workspace-scoped, lists paginated)
| Method | Path | Notes |

| POST | `/api/v1/sources/public` | add a public repository by URL (credential kind none) |
| GET | `/api/v1/sources/connections/{id}/repositories?search&page&size` | a connection's selectable repos via the adapter |
| POST | `/api/v1/sources/connections/{id}/select` | select repositories by the provider's id |

| (field) | `RepositoryView` | += provider, host, providerRepoId; gitlabProjectId now nullable |
| (field) | `SubIssueView` | += provider (selects the source-link shape) |

GitLab connection endpoints (`/api/v1/gitlab/connections`) are unchanged and now list every provider's
connections too. Tokens are entered only in the UI, encrypted at rest (AES-GCM), never logged, never in a URL or
env var; the scanner receives a token only via the D-014 one-time file (GitLab `oauth2`, GitHub `x-access-token`
basic-auth username; the token is the password).

## Decisions / D-drafts
- **D-089** (new): source host policy — built-in SaaS hosts (github.com, api.github.com, gitlab.com) allowed by
  default, switchable off with `SECSCAN_SOURCE_ALLOW_BUILTIN_SAAS=false` (D-033 egress lock); self-managed hosts
  stay deny-by-default via `SECSCAN_GITLAB_ALLOWED_HOSTS`. **D-085's single-GitLab-host restriction is retired.**
- **V0 decision (approval 12):** a public repository is its **own** `gitlab_connection` row (credential_kind
  'none', target_type 'repo', no token), not an anonymous per-host shared connection (rationale in the work log).
- **V0 decision (approval 14):** repository `host` backfill = own connection → single workspace host → single
  global host → RAISE (there is no repository URL column; a Flyway SQL migration cannot read the env allowlist).
- **D-draft (V1):** repository identity columns are filled on insert by a DB trigger as a compatibility shim so
  legacy GitLab insert paths needed no change; `host` is `@Generated(INSERT)` so it is never written on update.
