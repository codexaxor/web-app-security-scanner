# Milestone report: M2 Scan engine

Branch: `feature/m2-scan-engine` · Date: 2026-10-13 · Model(s) used: Claude Opus 4.8

M2 builds the scan pipeline end to end for one scanner — **secrets (Gitleaks)** — plus git: `scan`/`scan_task`/
`scan_job` (+ an interim `scan_finding`, D-024), the PostgreSQL job queue, the disposable scanner image, a
hardened docker-java launcher, and the output parser. SCA/SAST/IaC/EOL scanners (M4/M6) and the deduplicated
issue model (M3) are out of scope.

## What was built

- **Schema (V6)** — `scan`, `scan_task`, `scan_job`, `scan_finding`; all carry `workspace_id`. Partial unique
  index `uq_scan_active_per_repository` (one queued/running scan per repo); claim/lease indexes on `scan_job`.
- **Entities + repositories** (`app/.../scan/`) — `Scan`/`ScanTask`/`ScanJob`/`ScanFinding` with lifecycle
  methods; `ScanJobRepository.claimable`/`staleLeases` use `FOR UPDATE SKIP LOCKED`.
- **Scanner image** (`scanner-image/`, D-023) — digest-pinned Alpine + git + jq + checksum-pinned Gitleaks
  8.21.2. `run-scan.sh` clones one commit into tmpfs `/work`, runs `gitleaks dir` unredacted, and sanitizes
  **inside the container** to `/out/secrets.json` (rule id, repo-relative file, start line, SHA-256, 4-char
  preview) + a `result.json` manifest. Raw secret never leaves the container.
- **Parser** — core `RawFinding` (reused by M3) + app `ScannerOutputParser` → `ParsedScan`; the secret binding
  has no field for a raw value and ignores unknown JSON.
- **Hardened launcher** (`app/.../scan/worker/`, D-022/D-026) — `ScannerLauncher` + pure `ScannerContainerConfig`
  (read-only rootfs, tmpfs `/work`, cap-drop ALL, no-new-privileges, 2 CPU/4 GB/512 PIDs, no socket, token only
  as a read-only file, network=none for local clones); container always removed in a `finally`. `ScanWorkspace`
  (0700 dir / 0600 token, wiped in `close()`), `LogSanitizer` (core).
- **Queue + pipeline** — `ScanService`/`ScanEnqueuer` (Start Scan, one-in-flight dedup), `ScanClaimer` (claim +
  lease + stale-lease sweep), `ScanStateService` (short write txs), `ScanJobProcessor` (orchestration; provisional
  reachability probe before clone, change #2), `ScanPoller` (@Scheduled bounded pool, max-parallel).
- **M1b carry-over fix** — GitLab I/O removed from the `@Transactional` connection-update path (read → I/O →
  short write tx via `ConnectionTokenWriter`).
- **Ops** — Docker socket mounted into the worker only (D-026), `SECSCAN_SCAN_WORK_ROOT` same-path bind, the
  `buildScannerImage` Gradle task.

## Migrations

`V6__scan_engine.sql` and `V7__scan_workspace_indexes.sql` (V1–V5 untouched). Both apply to an empty DB
(`ScanMigrationIT`). V6 was first edited in place to add the `workspace_id` indexes, but it had already run on a
local dev DB; that broke Flyway checksum validation, so V6 was restored to its applied content and the indexes
moved to V7 (see "Review fixes" below).

**`V6__scan_engine.sql`** — in full:

```sql
-- M2: the scan engine. One scan = one repository at one commit. PostgreSQL is also the job queue (D-003):
-- scan_job rows are claimed with SELECT ... FOR UPDATE SKIP LOCKED, no Redis/broker.
--
-- Every business table carries workspace_id and every query filters by it (CLAUDE.md domain rule 1); the
-- spec's data-model table lists "key columns" only, so adding workspace_id to the child tables does not
-- contradict it. Findings parsed from a scanner are stored as raw scan_finding rows now (D-024); M3 reconciles
-- them into issue_group/sub_issue with stable fingerprints.

create table scan (
    id            uuid        primary key,
    workspace_id  uuid        not null references workspace (id),
    repository_id uuid        not null references repository (id),
    trigger       text        not null check (trigger in ('schedule', 'commit', 'manual')),
    commit_sha    text,
    status        text        not null
                    check (status in ('queued', 'running', 'completed', 'partial', 'failed')),
    -- Tool + rule versions recorded per scan (CLAUDE.md security rules); used by M9 skip-unchanged.
    tool_versions jsonb       not null default '{}'::jsonb,
    started_at    timestamptz,
    finished_at   timestamptz,
    created_at    timestamptz not null default now()
);

-- At most one in-flight scan per repository: a new Start Scan returns the existing queued/running scan rather
-- than enqueuing a second. Enforced here so a concurrent double-submit cannot create two (service recovers).
create unique index uq_scan_active_per_repository
    on scan (repository_id)
    where status in ('queued', 'running');

create index idx_scan_workspace on scan (workspace_id);
create index idx_scan_repository on scan (repository_id);

-- One row per scanner that ran in a scan; tracks partial-failure (CLAUDE.md domain rule 3: a scanner that
-- failed/timed out never closes its findings). M2 runs only the secret scanner (Gitleaks).
create table scan_task (
    id           uuid        primary key,
    workspace_id uuid        not null references workspace (id),
    scan_id      uuid        not null references scan (id) on delete cascade,
    scanner      text        not null,
    status       text        not null check (status in ('ok', 'failed', 'timed_out')),
    exit_code    int,
    duration_ms  bigint,
    -- Truncated and token-scrubbed before storage (never full tool output, never a secret value).
    log_excerpt  text,
    created_at   timestamptz not null default now()
);

create index idx_scan_task_scan on scan_task (scan_id);

-- The queue. state drives claiming; attempts/run_after drive retry with backoff; locked_by/locked_at are the
-- lease (a stale lease is requeued). Exactly one job per scan.
create table scan_job (
    id           uuid        primary key,
    workspace_id uuid        not null references workspace (id),
    scan_id      uuid        not null references scan (id) on delete cascade,
    state        text        not null check (state in ('queued', 'running', 'done', 'failed')),
    attempts     int         not null default 0,
    locked_by    text,
    locked_at    timestamptz,
    run_after    timestamptz not null default now(),
    created_at   timestamptz not null default now(),
    constraint uq_scan_job_scan unique (scan_id)
);

-- The claim query filters on state + run_after; the lease sweep filters on state + locked_at.
create index idx_scan_job_claim on scan_job (state, run_after);
create index idx_scan_job_lease on scan_job (state, locked_at);

-- Raw normalized findings (D-024, pipeline step 7). One row per finding per scan; no dedup/reconcile yet
-- (that is M3). Secret findings store only a SHA-256 hash and a 4-char masked preview, never the value
-- (CLAUDE.md security rules).
create table scan_finding (
    id                uuid        primary key,
    workspace_id      uuid        not null references workspace (id),
    scan_id           uuid        not null references scan (id) on delete cascade,
    repository_id     uuid        not null references repository (id),
    type              text        not null check (type in ('sca', 'sast', 'secret', 'iac', 'eol')),
    scanner           text        not null,
    rule_id           text,
    vuln_id           text,
    package           text,
    installed_version text,
    fixed_version     text,
    file_path         text,
    line              int,
    snippet_hash      text,
    secret_hash       text,
    secret_preview    text,
    tool_severity     text,
    created_at        timestamptz not null default now()
);

create index idx_scan_finding_scan on scan_finding (scan_id);
create index idx_scan_finding_repository on scan_finding (repository_id);
```

**`V7__scan_workspace_indexes.sql`** — in full:

```sql
-- M2 review fix: index workspace_id on the scan-engine child tables.
--
-- Every business table carries workspace_id and every query filters by it (CLAUDE.md domain rule 1), so each
-- of these columns wants an index. They were first added inside V6, but V6 had already been applied to a local
-- dev database, so editing it in place broke Flyway's checksum validation. Migrations are immutable once run
-- on ANY database (CLAUDE.md), so the indexes live here in a new migration instead.
--
-- scan already has idx_scan_workspace from V6; these cover scan_task, scan_job and scan_finding.
-- "if not exists" keeps this idempotent for any database where the indexes were created by the edited V6.

create index if not exists idx_scan_task_workspace on scan_task (workspace_id);
create index if not exists idx_scan_job_workspace on scan_job (workspace_id);
create index if not exists idx_scan_finding_workspace on scan_finding (workspace_id);
```

## Deviations from SPEC.md

- `scan_finding` is an interim store not in the spec's data model (D-024); M3's reconcile consumes it into
  `issue_group`/`sub_issue`.
- `scan_task`/`scan_job`/`scan_finding` carry `workspace_id` (CLAUDE.md rule 1) though the spec's "key columns"
  list omits it for child tables.
- M2 scans the checked-out tree (`gitleaks dir`); full git-history secret scanning is deferred (Known gaps).
- `scan_warning` (inventory warnings) is not created yet — it belongs with SCA/lockfile detection in M4.
- Backend only; no UI this milestone (Repositories/Feed screens are M8).

## Bugs found during the manual run (fixed here)

1. **Compose did not pass `SECSCAN_GITLAB_ALLOWED_HOSTS` to api/worker** — the SSRF allowlist (D-018) was empty
   in the containers, so every outbound GitLab call was denied. The user added the env line to both services by
   hand; that edit is reviewed, kept and committed (`docker-compose.yml`). To make the condition visible,
   `GitLabHostPolicy` now logs its effective allowlist at startup and **WARNs loudly when it is empty** (empty =
   deny all). Covered by `GitLabHostPolicyTest.startupSummaryWarnsWhenEmpty` /
   `startupSummaryListsConfiguredHosts`.
2. **A compose smoke test wiped the dev database** — an earlier ad-hoc `docker compose … down -v` ran against the
   **default** project and deleted the shared `postgres-data` volume. Fixed by a dedicated, isolated
   `scripts/compose-smoke.sh`: it runs under its own project (`-p secscan-smoke`, namespaced
   `secscan-smoke_postgres-data` volume), uses ephemeral host ports so it can't clash with a running dev stack,
   and scopes teardown to `-p secscan-smoke` so `down -v` can never touch the default volume. The rule ("never
   `down -v` the default project; smoke runs use `-p secscan-smoke`") is documented in README and CLAUDE.md.
3. **Secret scan covers current files only** (no git history) — see Known gaps; expected for M2.

## Review fixes (2026-10-14, post-review)

Applied after `/review-pr M2` and the owner's review, on `feature/m2-scan-engine`:

1. **Gitleaks exit codes hardened.** `run-scan.sh` now runs `gitleaks dir … --exit-code 2`; a run is successful
   only when the exit code is 0 (clean) or 2 (leaks) **and** the JSON report is a valid array. Any other exit
   code (gitleaks returns 1 on error), or a missing/invalid report, is a scanner failure (`status: "failed"`,
   process exit 20). Verified empirically against the real image (clean→0/`[]`, leak→2, bad path→1/no report).
   Test: `ScanQueueIT.aScannerFailureMakesTheScanPartialWithNoFindings` (task failed, scan **partial**, no
   findings stored).
2. **Keyed secret hash (D-027).** The worker stores `secret_hash = HMAC-SHA256(SECSCAN_FINGERPRINT_KEY, the
   container's SHA-256)`, hex — the bare SHA-256 is never persisted. Key is 32-byte base64; invalid → startup
   fails; missing → a clear error when a secret finding must be stored (never a bare-digest fallback). New
   `SecretFingerprinter` (core, `SecretFingerprinterTest`) + `SecretFingerprinterHolder`/`FingerprintConfig`
   (app), wired in `ScanStateService`. `ScanPipelineIT`/`ScanQueueIT` now expect the HMAC. Var added to
   `.env.example`, `docker-compose.yml`, README.
3. **Preview rule.** The container reveals the first 4 characters only when the secret is ≥ 12 chars long,
   otherwise `****` (`secret_preview` in `scanner-image/secscan-lib.sh`). Test: `MaskPreviewScriptTest` runs the
   real shell function.
4. **`memorySwap == memory`** on the scanner container, so the memory cap cannot be evaded by swapping
   (`ScannerContainerConfig`; asserted in `ScannerContainerConfigTest`).
5. **Launcher timeout accuracy.** `ScannerLauncher` reports `timedOut=true` only when the wait actually elapses
   (`awaitCompletion` returns false); any other Docker error is logged clearly and rethrown, never mislabelled
   as a timeout. Container still removed on every path. Test: `ScannerLauncherTest`.
6. **Symlinks.** Confirmed `gitleaks dir` does not follow symlinks (we never pass `--follow-symlinks`); comment
   added in `run-scan.sh`.
7. **Log-excerpt assertion.** `ScanPipelineIT` now asserts the stored `scan_task.log_excerpt` contains neither
   the raw fake key nor the fixture's AWS secret-access-key value.
8. **Status semantics aligned to SPEC step 12.** A run where the clone succeeded but a scanner failed is now
   `partial` (SPEC: "complete, or partial if any scanner failed"), not `failed`; `failed` is reserved for a scan
   that could not run (clone failure, timeout, missing result, infra/config error). `deriveTerminalStatus` and
   `Scan`'s javadoc updated.
9. **Migration.** `workspace_id` indexes added on `scan_task`/`scan_job`/`scan_finding`. First added by editing
   V6 in place, but V6 had already run on a local dev DB, so Flyway rejected the changed checksum. Fixed without
   resetting the DB: V6 was restored to its applied content and the three indexes moved to a new
   `V7__scan_workspace_indexes.sql` (`create index if not exists …`). Both migrations are pasted in full under
   "Migrations" above. New rule in CLAUDE.md: never edit a migration once it has run on any database (including a
   local dev DB) — always add a new one.

## Post-plan fix: worker UID/permission model (real-run bug)

The first real `docker compose` run failed with `AccessDeniedException` creating `$SECSCAN_SCAN_WORK_ROOT/<scanId>`:
the host work root is owned by the host user, but the worker container ran as the image's `secscan` user
(uid 10001). The in-process ITs missed this because they run as the host user. Fixed end to end:

1. **Compose runs the worker as the host user** — `user: "${SECSCAN_UID}:${SECSCAN_GID}"` plus
   `group_add: ["${DOCKER_GID}"]` for the Docker socket. `.env.example` documents `id -u` / `id -g` /
   `stat -c %g /var/run/docker.sock`.
2. **The launcher runs each scanner container as that same uid:gid** (the owner of the per-scan dir; still
   non-root with cap-drop ALL etc.), so it can read the token file and write `/out`.
3. **Worker startup self-check** (`ScannerEnvironmentCheck`, worker profile): work root writable, Docker daemon
   reachable, scanner image present; logs one clear error and does **not** claim jobs until healthy, rechecking
   every 60s.
4. **Configuration errors are not retried** — work root not writable, Docker unreachable, image missing →
   `ScanStateService.failPermanently` fails the scan once with a clear reason instead of burning 3 attempts.
5. **Compose smoke** run and recorded (see Evidence) — the gap the unit/ITs missed.
6. **README** documents the work-root setup (mkdir + chown, same absolute path in compose) and the self-check.

Tests added: `ScannerEnvironmentCheckTest` (ready flips on image/daemon/work-root), `ScanQueueIT`
`aMissingScannerImageFailsTheScanWithoutRetry`.
