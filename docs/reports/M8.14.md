## What was built
- `app/.../scan/worker/ScanReaper.java` — container phase (both-label daemon filter, live check + removal under
  the `ActiveScans` lock) and dir phase (own instance sub-tree only, NOFOLLOW + real-path containment, per-child
  fault isolation, best-effort `walkFileTree` delete); `reapBeforeFirstClaim()` startup gate; periodic
  `@Scheduled` sweep (`secscan.scanner.reap-interval-ms`, default 10 min); counts-only logging.
- `app/.../scan/worker/ActiveScans.java` — reference-counted live-scan registry; `runIfInactive` / `underLock`.
- `app/.../scan/worker/ScanJobProcessor.java` — registers the scan before the workspace/container exist, releases
  it in a `finally` after both are gone; creates the workspace under the registry lock, replacing a dead run's dir

- `ScannerProperties` (`instanceId`, `reapIntervalMs`), `ScannerLaunchSpec`/`ScannerContainerConfig`/`ScannerLauncher`

## Manual steps (one-time, after merge)
Leftovers created BEFORE this change are deliberately never touched by the reaper. With the worker stopped:
- Old-layout scan dirs directly under the work root (they may contain token files):
  `find /var/lib/secscan/scans -mindepth 1 -maxdepth 1 -type d -regextype posix-egrep
  -regex '.*/[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}' -print` → review, then delete
  (`-exec rm -rf {} +`). The new layout keeps everything under `<workRoot>/<instanceId>/`.
- Unlabelled pre-change scanner containers (logged once at INFO by the reaper):
  `docker ps -a --filter label=secscan.component=scanner --format '{{.ID}} {{.Label "secscan.instance"}}'` → remove
  the ones with an empty instance with `docker rm -f <id>`.

## Known gaps / TODOs
- **Lease not renewed during long scans (→ M9).** `scan_job` leases are never renewed; if processing outlasts
  `timeout + lease-margin` (default 35 min) the stale-lease sweep may requeue a job that is still running, and the
  same or another worker may claim it again. M8.14 makes this safe for the reaper (refcount; a busy workspace is
  retried, not deleted), but the duplicate run itself remains — add lease heartbeats/renewal in M9.
- One worker per instance id (D-102): two workers sharing an id could still reap each other's live leftovers.
- The container half of "released only after the container is gone" rests on `ScannerLauncher`'s own `finally`
  removal (covered by `ScannerLauncherTest`); `ScanJobProcessorLifecycleTest` stubs the launcher.
- `DirectoryIteratorException` (the listing itself failing mid-way) is handled but not unit-tested — not
  reproducible on a local filesystem.
