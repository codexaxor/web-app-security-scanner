## 2. Routing changes (D-103)

- **"/"** renders the public `HomePage` (outside the app shell). **`/login`** renders `LoginPage` (wraps the
  unchanged `SignInGate`); **`/signup`** renders the M8.10 `SignUpPage`. Both sit in the new `AuthShell`:
  `main` landmark, brand linking to "/", "← Back to home".
- **Removed:** the in-place sign-in gate in `Layout` (signed out, any route used to render the gate or — at
  `/signup` — the sign-up form instead of the shell) and the `SIGNUP_PATH` export.
- **Signed-out app route →** `<Navigate to="/login?next=<pathname+search>" replace>`. `/login` signed in →
  `<Navigate to={safeNextPath(next)}>` (default `/dashboard`).
- **Explicit Sign out →** plain `/login` (`AuthProvider.signedOutByUser`, reset on sign-in). An expired session
  (401) still carries `next`.
- **Session check in flight:** shell → empty busy `main`; `/login` → busy frame, no form; "/" → invisible CTA
  placeholders (`data-testid="cta-pending"`). No flash of app content, of the form, or of "Sign in / Create
  account" for a signed-in visitor.
- `SignUpPage` links "Sign in" / "Back to sign in" now point to `/login` (were "/").
- App routes keep their paths; the catch-all inside the shell still redirects to `/dashboard`.

## 3. `safeNextPath` (`ui/src/lib/safeNext.ts`) — rules and tests

Kept only if: (1) non-empty string; (2) starts with exactly one "/" (not "//", not "/\"); (3) no backslash
anywhere; (4) no ASCII control char and no whitespace (JS `\s`, so Unicode spaces incl. U+3000 too); (5)
resolved against a sentinel origin it stays on that origin. Otherwise → `/dashboard`.

Tests (`ui/src/lib/safeNext.test.ts`): same-origin paths with query kept; null/undefined/"" fall back;
`//evil.com`, `///evil.com`, `/\evil.com`, `\/evil.com`, `https://…`, `http://…`, `javascript:alert(1)`,
`data:…`, `evil.com`, `/ /evil`, `/evil\nX` rejected; **review round:** `%2F%2Fevil.com`, `%252F%252Fevil.com`,
`/\tevil`, `\t//evil.com`, `/　/evil`, `　//evil.com`, `JAVASCRIPT:alert(1)`, `JaVaScRiPt:alert(1)`
rejected; a once-decoded double-encoded `next` never resolves off-origin; custom fallback honoured.
Route level (`ui/src/App.test.tsx`): `%2F%2Fevil.com`, `https%3A%2F%2Fevil.com`, `%2F%5Cevil.com` → `/dashboard`.
e2e (`homepage.spec.ts`): `/login?next=//evil.example` → sign-in lands on `/dashboard`.

## 4. `/auth/session` probe kept on "/"

The AuthProvider boot check (D-092) still runs on every page, including "/": the homepage needs it to show a
signed-in visitor "Open dashboard" instead of "Sign in / Create account". The homepage itself fetches nothing
(`HomePage.test.tsx` "makes NO API calls when signed out"); e2e "the homepage makes no business-API calls when
signed out" waits for the `/api/v1/auth/session` response and asserts it is the only `/api/` request.

## 10. Open items / Deferred

- **Over-scoped tokens (deferred, register):** GitLab token setup should warn/refuse tokens carrying `api` or
  `write_repository` scopes — backend, separate milestone. GitHub fine-grained PATs cannot be inspected.
- **Crash/restart cleanup:** no reaper on develop — an orphaned container + host workspace dir (incl. the one-time
  token file) can linger after a worker crash. D-102 (M8.14 reaper) addresses it; the homepage makes no crash
  claim until it merges.
- **Scanner egress:** the container's SCA egress (osv.dev/deps.dev) is on the open bridge, not a host allowlist;
  the homepage makes no allowlist or offline claim.
- **Behaviour change, not yet addressed:** a signed-in visitor at `/signup` now sees the sign-up form (on develop
  the shell's catch-all sent them to `/dashboard`). Harmless (a request only creates a pending sign-up); a
  redirect to `/dashboard` is a small follow-up.
